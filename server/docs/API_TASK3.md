# Task 3 API — Trip Intelligence & Risk Scoring

This document describes the fleet **intelligence layer**: trip completion, behavioural feature extraction, explainable risk scoring, and weekly fleet summaries.

## Architecture

```
GPS readings + alerts (PostgreSQL)
        ↓
Feature extraction  (`server/src/services/tripFeatures.js`)
        ↓
Risk model          (`server/src/services/riskModel.js`)
        ↓
Risk score (0–100) + label + risk factors
        ↓
Stored on trip + returned via API
```

**Important:** The current AI component is a **lightweight explainable weighted risk model**, not a trained machine-learning model. It uses measurable features from trips generated by this system. The scoring module is isolated so it can later be replaced by a trained ML model without rewriting ingest, rules, or API handlers.

---

## Endpoints

### `POST /api/trips/:id/end`

Ends an active trip and calculates risk.

**Behaviour:**
1. Finds the trip (404 if missing)
2. If already completed → returns existing risk data with `alreadyCompleted: true` (safe to call again)
3. Sets `ended_at`, `status = completed`
4. Loads GPS readings and alerts
5. Extracts behavioural features
6. Calculates risk score, label, and factors
7. Persists `risk_score`, `risk_label`, `risk_factors` on the trip
8. Sets vehicle to `idle` if no other active trips exist

**Example response:**
```json
{
  "id": "uuid",
  "vehicleId": "uuid",
  "plateNumber": "AB12 CDE",
  "driverName": "Alex Morgan",
  "startedAt": "2026-08-25T10:00:00.000Z",
  "endedAt": "2026-08-25T10:05:00.000Z",
  "status": "completed",
  "riskScore": 24,
  "riskLabel": "low",
  "riskFactors": ["No significant behavioural violations detected"],
  "distanceM": 1250.5,
  "durationSeconds": 300,
  "alreadyCompleted": false
}
```

### `GET /api/trips`

Lists trips with summary fields.

**Query parameters (optional):**
| Param | Description |
|-------|-------------|
| `vehicleId` | Filter by vehicle UUID |
| `status` | `active` or `completed` |
| `from` | ISO timestamp — trips starting on/after |
| `to` | ISO timestamp — trips starting before |

**Response fields:** `id`, `vehicleId`, `plateNumber`, `driverName`, `startedAt`, `endedAt`, `status`, `speedLimitKmh`, `readingCount`, `alertCount`, `distanceM`, `durationSeconds`, `riskScore`, `riskLabel`

---

### `GET /api/trips/:id`

Full trip detail for the Trip Detail screen.

**Includes:** trip info, vehicle, driver, readings, alerts, planned route (if configured), distance, duration, speed stats, `riskScore`, `riskLabel`, `riskFactors`, and extracted `features` object.

---

### `GET /api/summary/weekly`

Weekly fleet statistics from the database.

**Query parameters:**
| Param | Description |
|-------|-------------|
| `week` | Optional ISO date (`YYYY-MM-DD`) within the target week. Defaults to current week. |

**Week bounds:** Monday 00:00 UTC to next Monday 00:00 UTC.

**Response (minimum):**

## Feature extraction

Calculated from stored GPS readings and alerts (`tripFeatures.js`):

| Feature | Source |
|---------|--------|
| Average speed | Mean of `speed_kmh` readings |
| Maximum speed | Max `speed_kmh` |
| Speed limit | Trip `speed_limit_kmh` |
| Maximum speed ratio | max speed ÷ limit |
| Overspeed count | Readings where speed > limit |
| Critical overspeed count | Readings where speed > limit × 1.2 |
| Restricted-zone violations | Alerts `type = restricted_zone` |
| Out-of-hours violations | Alerts `type = out_of_hours` |
| Route-deviation violations | Alerts `type = route_deviation` |
| Total alert count | All trip alerts |
| Trip duration | `ended_at − started_at` (seconds) |
| GPS reading count | Row count |
| Distance travelled | Sum of `distance_m` (Haversine segments from ingest) |

Alert-based overspeed event counts (deduplicated rule events) are used for risk scoring; reading-based counts are included in the features object for transparency.

## Risk model

**Module:** `server/src/services/riskModel.js`

Score starts at **0**. Weighted contributions:

| Factor | Weight |
|--------|--------|
| Overspeed alert (warning) | +12 each |
| Critical overspeed alert | +25 each |
| Restricted-zone entry | +28 each |
| Out-of-hours movement | +15 each |
| Route deviation | +12 each |
| Max speed ratio > 1.0 | up to +25: `(ratio − 1) × 50`, capped |
| Avg speed > 90% of limit | up to +12: `(ratio − 0.9) × 40`, capped |

Final score: `min(100, round(raw))`

**Labels:**
| Score | Label |
|-------|-------|
| 0–33 | `low` |
| 34–66 | `medium` |
| 67–100 | `high` |

**Risk factors:** Human-readable strings derived from measured counts, e.g. `"2 overspeed events"`, `"1 restricted-zone entry"`.

## Database

Uses existing `trips.risk_score` and `trips.risk_label`.

**Added column:**
- `trips.risk_factors JSONB DEFAULT '[]'` — stores explanation strings at trip end so detail views do not need to recompute.

Migration: `npm run db:migrate:task3`  
Fresh setup: `npm run db:reset` (includes column in `schema.sql`).
